# deeper-prompt

> 名字取自核心原则「**要更深，不要更大**」（deeper, not bigger）。
> 一个在**执行前**把任意提示词升级为「更深版本」的 skill——而不是拿到任务就直接开干。

方法论来自 **Felix Rieseberg**（Anthropic 工程经理，曾负责 Claude.ai、Cowork、
Claude Code 桌面版工程团队）的文章
[How to be more ambitious: A tutorial for humans with models](https://felixrieseberg.com/how-to-be-more-ambitious-a-tutorial-for-humans-with-models)（2026-10-13）。

## 它做什么

把「拿到任务直接干」替换为五阶段循环：

```
侦察 → 深度四问 → 广度扩展 → 重写提示词 → 用户确认 → 执行
```

- **要更深，不要更大**——升级方法、工具、原始材料和验收标准，而不是堆输出量
- **禁止专家角色扮演**——「你是一位资深 XX」只换词汇不换方法；改为借用顶尖从业者
  真正使用的工具和原始材料
- **绝不让模型自评**——每次重写都附带模型之外的外部验证手段（测试、基准、可自动
  运行的检查）
- **先升级提示词，再执行**——交付物是重写后的提示词，经你确认后才开始干活

## 核心提示词

> 我要的是这个任务更深的版本，而不是更大的版本。在重写之前，请先：
> (1) 说出这个领域的顶尖专业人士在这里会做、而我没有要求的事；
> (2) 指出他们会从哪种最原始的材料入手，而不是那些已经被消化过的二手信息；
> (3) 说出他们会用的具体方法和工具；
> (4) 说明除了你和我之外，还有什么能证明结果是对的。
> 然后把我的提示词改写成恰好要求做到这些的样子。

## 为什么传统的「五层提示词设计」不够

社区流行的提示词设计通常分五层：**角色层**（你是一位资深 XX）、**背景层**、
**任务层**、**约束层**、**输出格式层**。这套设计优化的是「请求的表达方式」，
但它有天花板：

| | 传统五层设计 | 野心方法论（本 skill） |
|---|---|---|
| 优化对象 | 提示词**怎么说** | 任务**怎么做**：方法、工具、数据、验收 |
| 专家如何进入 | 角色层里「扮演」专家——模型只切换词汇，不切换方法 | 借用专家的**工具、原始材料、工作动作**（数据库/统计模型，不是表格） |
| 数据 | 背景层给的是用户手里的二手加工材料 | 强制回溯**最原始材料**（日志/财报/源代码），缺就向用户要 |
| 目标 | 任务层按用户原样转述 | 定**高一个数量级**的目标并声明合理（10 秒 → 5 秒 → 200 毫秒） |
| 验收 | 约束层只能约束格式，质量靠模型自评或人眼 | 强制**外部裁判**：测试、基准、可自动运行的检查，不许自评 |
| 结构 | 五层写完 → 直接执行 | 四问自检 → **先重写提示词** → 确认 → 再执行 |

一句话：五层设计把一个平庸任务**包装**得更好；野心方法论把任务本身**换掉**。
五层可以保留——野心框架重写后的提示词同样可以用五层格式承载，但决定质量的是
目标、原始材料、工具和外部验证这四样，而这四样恰恰是五层设计覆盖不到的。

## 目录结构

```
deeper-prompt/
├── SKILL.md                    # Skill 入口（中文）——工作流、自检清单、反模式
├── SKILL.en.md                 # Skill 入口英文完整镜像
└── references/
    ├── methodology-zh.md       # 完整中文方法论（案例库、提示词原文、出处）
    └── methodology-en.md       # 完整英文方法论
```

## 安装

把 `deeper-prompt/` 文件夹复制到你的 agent skills 目录：

- WorkBuddy（用户级）：`~/.workbuddy/skills/deeper-prompt/`
- Claude Code：`~/.claude/skills/deeper-prompt/`

然后说「帮我升级这个提示词」「我要这个任务更深的版本」「stress-test this prompt」
等即可触发。（`SKILL.md` 为入口文件；`SKILL.en.md` 是英文镜像，供阅读参考。）
